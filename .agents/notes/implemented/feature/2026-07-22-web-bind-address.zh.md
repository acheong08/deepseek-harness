# Agent Note: 显式指定 Web 绑定地址

Status: implemented

[English](2026-07-22-web-bind-address.md) | 中文

## 问题

即便浏览器与服务器运行在同一台机器上，`dsh web` 也会绑定所有网络接口。因此，本地使用会在操作者未明确选择的情况下暴露一个未经身份验证的开发服务器；另一方面，远程容器和局域网浏览器场景仍需要一种受支持的方式来接受非环回连接。

HTTP 承载层还把绑定地址隐藏在 `startWebServer()` 内部，导致其他壳层无法在包边界明确表达自己的网络策略。

## 决策

`dsh web` 默认绑定 `127.0.0.1`。CLI（命令行界面）接受 `--host 127.0.0.1` 与显式内部 IPv4 字面量（RFC1918 或 `100.64.0.0/10`），同时继续拒绝 `--host 0.0.0.0`，因此普通本地使用仍保持为纯环回，而 mesh 或 LAN 访问必须点名一个经过审慎选择的地址，而不是全部接口。

`WebServerOptions.host` 为必填项。HTTP 承载层将该值直接传给 `node:http`，不提供回退值，因此每个壳层负责制定自己的绑定策略。以编程方式使用承载层的消费方仍可直接选择 `0.0.0.0` 或其他受支持的绑定地址。

## 曾考虑的替代方案

**保留以 `0.0.0.0` 作为默认值。** 不予采纳，因为普通的同机使用不需要在全网范围内可达，也不应隐式获得这种可达性。

**使用布尔型暴露标志。** 不予采纳，因为绑定宿主本身就能直接说明最终的套接字行为，并与底层服务器选项一致，无需再引入第二套术语。

**在 `startWebServer()` 内设置默认值。** 不予采纳，因为承载层可能由多种壳层调用，没有依据替它们选择部署策略。要求传入 `host`，可使每次装配调用都明确作出这一选择。

## 后果

`dsh web` 的本地启动仍可通过 `http://127.0.0.1:3080` 访问；其他机器上的浏览器必须使用 `dsh web --host <internal-ipv4>` 显式启用。CLI 仍未开放 `0.0.0.0` 或 IPv6 模式，而以编程方式使用承载层的消费方保留更宽的灵活性。服务器测试将环回、通配和显式内部 IPv4 校验固定为 Node 监听边界的约定，Web 冒烟测试继续覆盖默认 CLI 路径。
